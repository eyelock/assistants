# @eyelock-assistants/platform-skills

## 0.2.0

### Minor Changes

- [#67](https://github.com/eyelock/assistants/pull/67) [`e41695c`](https://github.com/eyelock/assistants/commit/e41695c7c61341880ae7985c14c1e71ee8fae23b) Thanks [@eyelock](https://github.com/eyelock)! - Add an `apple-calendar` platform skill and harness. It reads Apple Calendar on a Mac through `che-ical-mcp` (iCloud, Google and Exchange calendars) for unanswered invites, replies pending on invites you organized, clashes, and `catch-up` and `find`. `my-commitments` is not answered there. The server has no read-only mode, so a `before_tool` hook blocks every tool of the server except six calendar read tools; a test pins the hook's pattern against all 29 tools. macOS Calendar access is read and write, so the hook is the only barrier. "Since" is unknown, because the server returns no creation date.

- [#53](https://github.com/eyelock/assistants/pull/53) [`1c21850`](https://github.com/eyelock/assistants/commit/1c21850acf60c4ee0d631f581ea65a1c585a04e7) Thanks [@eyelock](https://github.com/eyelock)! - Add an `imessage` platform skill and a read-only `imessage` harness. The harness runs `imessage-mcp` with full message text by default, with `redacted` and `counts` profiles for less.

- [#52](https://github.com/eyelock/assistants/pull/52) [`b18b930`](https://github.com/eyelock/assistants/commit/b18b930433c55e6798cb503f250911edd0dd40c4) Thanks [@eyelock](https://github.com/eyelock)! - Add platform-skills, a package of vendor skills (how to work well in one tool through its MCP server): `slack`, `github`, `gmail`, `google-calendar` and `google-drive`. Each platform harness includes its own skill and keeps only what is specific to its server and credentials.

  Breaking: the `calendar` and `drive` harnesses are renamed `google-calendar` and `google-drive`. Anyone who installed the old names must reinstall under the new ones.

- [#55](https://github.com/eyelock/assistants/pull/55) [`24d4db6`](https://github.com/eyelock/assistants/commit/24d4db6de765c95c190f0ed98cd49fbcf7966c6d) Thanks [@eyelock](https://github.com/eyelock)! - Switch the Slack harness and skill to Slack's official MCP server (`https://mcp.slack.com/mcp`). Breaking for anyone who ran the Docker-based community server: the token is now `SLACK_USER_TOKEN` (a user token with read scopes and the Slack MCP server setting enabled on the app), replacing `SLACK_MCP_XOXP_TOKEN`. The skill is rewritten for the official tools: there is no unreads or mentions tool, so waiting items are assembled from searches and thread reads, within a stated window.

### Patch Changes

- [#56](https://github.com/eyelock/assistants/pull/56) [`4afa5a5`](https://github.com/eyelock/assistants/commit/4afa5a56f87b4f60cc5fa9cc9bd36d9a889acc49) Thanks [@eyelock](https://github.com/eyelock)! - The `imessage` harness now reads message text by default (`--privacy full`), because triage cannot tell a question from a thank-you or a reply without it. Profile `redacted` hides the text, and `counts` is unchanged. The profile named `full` is gone, and `commitments`, `catch-up` and `find` no longer need to select it. The skill's notes say that in `redacted` mode every chat you spoke last in looks alike, so those are candidates, not confirmed waits.

- [#66](https://github.com/eyelock/assistants/pull/66) [`a53c455`](https://github.com/eyelock/assistants/commit/a53c45508ade5ea6e88517b9f54b0d8c0353164a) Thanks [@eyelock](https://github.com/eyelock)! - Pin the Google Workspace MCP server to `workspace-mcp@2.1.0`. Unpinned, `uvx` fetched whatever version was newest each time the harness started, for a server that holds the user's Google OAuth credentials.

- [#71](https://github.com/eyelock/assistants/pull/71) [`703ed70`](https://github.com/eyelock/assistants/commit/703ed70461c362591cd3b388bff6f6efaf480bf0) Thanks [@eyelock](https://github.com/eyelock)! - The `slack`, `gmail` and `github` evals have been run on Sonnet and fixed. Their descriptions now cover finding where someone said something (and, for `gmail`, saved tool results and emails that contain instructions), so the skills load in those cases. Assertions that tested the generic `find` skill's rules (the Searched line, withholding secrets) are removed, and several "does not list" assertions now allow mentioning an item as already handled.

- [#54](https://github.com/eyelock/assistants/pull/54) [`401b88b`](https://github.com/eyelock/assistants/commit/401b88b16e5ab0c00ffa6ce7fa1b2626103b0ab5) Thanks [@eyelock](https://github.com/eyelock)! - A time window now bounds only new asks (mentions, messages, mail). Standing items such as open review requests, assignments and unanswered invites are queried by state with no date filter and show their age. Automated senders collapse into one row per kind, after the people. The GitHub skill documents the `notifications` token scope.
