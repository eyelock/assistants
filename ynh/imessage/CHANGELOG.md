# @eyelock-assistants/imessage

## 0.2.0

### Minor Changes

- [#56](https://github.com/eyelock/assistants/pull/56) [`4afa5a5`](https://github.com/eyelock/assistants/commit/4afa5a56f87b4f60cc5fa9cc9bd36d9a889acc49) Thanks [@eyelock](https://github.com/eyelock)! - The `imessage` harness now reads message text by default (`--privacy full`), because triage cannot tell a question from a thank-you or a reply without it. Profile `redacted` hides the text, and `counts` is unchanged. The profile named `full` is gone, and `commitments`, `catch-up` and `find` no longer need to select it. The skill's notes say that in `redacted` mode every chat you spoke last in looks alike, so those are candidates, not confirmed waits.

- [#53](https://github.com/eyelock/assistants/pull/53) [`1c21850`](https://github.com/eyelock/assistants/commit/1c21850acf60c4ee0d631f581ea65a1c585a04e7) Thanks [@eyelock](https://github.com/eyelock)! - Add an `imessage` platform skill and a read-only `imessage` harness. The harness runs `imessage-mcp` with full message text by default, with `redacted` and `counts` profiles for less.

- [#57](https://github.com/eyelock/assistants/pull/57) [`8b544e4`](https://github.com/eyelock/assistants/commit/8b544e403c1d861d63ae4c8d29b6fb380376d66f) Thanks [@eyelock](https://github.com/eyelock)! - The common triage list grows by three questions, `my-commitments` (what I promised and have not done), `catch-up` (where a conversation, thread or topic stands) and `find` (where something was said), and `add-triage-question` says when a new question belongs on the list and when it does not, keeps every platform harness in step with the list (`scripts/triage-questions.mjs check` and `sync`), and is checked by `pnpm test`. The iMessage harness is the first to answer all of them; the others are marked `todo` in the list and follow in their own changes. The iMessage `commitments` focus is renamed `my-commitments`.
