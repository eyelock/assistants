Five rule sensors, declared in the plugin's manifest as blocking `command` sensors and run by `ynh check` in CI on a Wheelhouse repository: `includes-pinned` (a git include with no `ref`), `references-exist` (the constitution or a charter names a path, skill or seat that is not there), `roster-consistent` (the roster, the harness folders, the desk's delegates and the charters disagree on who the seats are; a seat not started by its own name; not exactly one default human), `no-forked-scripts` (a copy of a plugin script) and `work-in-beads` (no work graph, or Beads' own agent setup). Each is a plain-bash script under `sensors/rules/` that runs without ynh, with a fixture built to trip it under `sensors/fixtures/` (so `ynh check --calibrate` reports all five calibrated) and offline tests. The doctor's four checks of a Wheelhouse's own files (plugin script copies, seats wired, default human, no Beads agent setup) moved into `skills/doctor/scripts/static-checks.sh`, which `check.sh` and the sensors both run; the doctor's report is unchanged. A `pick` include of the plugin carries all its sensors, so an include that must not carry them needs `"sensors": false` (README).
