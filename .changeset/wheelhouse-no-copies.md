A Wheelhouse keeps no copies of the plugin's scripts: seats run them where ynh installed them, in the `scripts/` folder of the skill that owns each. `create-wheelhouse` copies nothing (its step 5 now says so), and `refresh --update` runs `ynh update` and copies no script; its report loses `pluginScriptsDiffer`, `pluginScriptsCopied` and `pluginScriptsKept`, and its `--plugin` option is gone. The session-start and session-end hooks that `create-wheelhouse` and `add-seat` write no longer run `bash scripts/wake.sh`: they try each vendor's plugin root (`CLAUDE_PLUGIN_ROOT`, `PLUGIN_ROOT`, `CURSOR_PLUGIN_ROOT`, then the run directory's `.codex`, `.cursor` and `.opencode`) and run the installed `wake.sh` (the `wake` skill's "The hook command"; checked live on Claude Code, the other vendors' roots are from their documentation). Every skill says where its scripts are (`<skills>/<skill>/scripts/`) and every command in the skills, the starter-team charters and the tutorial names the installed path. The scripts follow: `wake.sh` and `inbox.sh` print their retire command with the installed `memory.sh`'s path, and `wake.sh`, the doctor and refresh find `memory.sh` and `inbox.sh` in the work-graph skill only. The doctor stops requiring `scripts/memory.sh`, `scripts/wheelhouse-lib.sh` and `scripts/inbox.sh`; it errors when the work-graph skill's `memory.sh` or `inbox.sh` is missing from the seat's install, and warns about each copy of a plugin script left in a Wheelhouse's `scripts/` (delete it). The one exception stays: the bare-session guard, which a plain session runs with no ynh.
